# GlowGuide ML Service

This is the image-and-quiz fusion service for GlowGuide Skin Analysis. It uses two Hugging Face image classifiers and is deployed as a Docker container on Render. The Docker build downloads both models into an image layer, so inference does not download models at runtime.

## Local Run

From this directory:

```bash
export ML_SERVICE_SECRET="a-local-secret"
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 7860
```

The first local startup downloads the models unless they are already cached. Add six images to `sample_images/` using these names (any of jpg, jpeg, png, or webp — the test script detects the extension and sends the correct content type):

```text
front
left_profile
right_profile
forehead_closeup
left_cheek_closeup
right_cheek_closeup
```

Each image must be a JPG, JPEG, PNG, or WebP, at least 480x480, and no larger than 8MB. The `front`, `left_profile`, and `right_profile` images must contain a detectable face; the three closeups are sent to the acne model and may focus on a forehead or cheek region. Export the same secret for the service and test script, then run:

```bash
export ML_SERVICE_SECRET="a-local-secret"
python test_analyze.py
```

The test script spins up a tiny local HTTP server on port 9999 (configurable via `CALLBACK_PORT`) to receive the callback. It expects 202 back immediately, then waits for the callback POST to arrive with the full result. The test script and sample images are ignored by Git. Use genuine face images for the three full-face fields; closeups should show the skin region being analyzed.

## API

### POST /analyze (Asynchronous)

This endpoint validates the request **synchronously** and returns **202 Accepted** immediately. Model inference runs in a background task and the result is delivered via a **callback POST** to the provided URL.

#### Request

`POST /analyze` requires the `X-Internal-Secret` header and a `multipart/form-data` body.

**Required image fields (6):**

```text
front
left_profile
right_profile
forehead_closeup
left_cheek_closeup
right_cheek_closeup
```

**Required form fields:**

| Field | Type | Description |
|---|---|---|
| `quiz_scores` | JSON string | Seven numbers (0–100): `sebum_level`, `hydration_level`, `acne_frequency`, `pore_size`, `sensitivity_score`, `roughness_score`, `tightness_score` |
| `analysis_id` | string | Firestore document ID, generated by the caller before this request |
| `callback_url` | string | Full URL to POST results to when inference completes. Must be `http(s)`, not a loopback address (`localhost`, `127.x`), and not a cloud metadata/internal endpoint (e.g. `169.254.169.254`, `*.internal`). `host.docker.internal` is allowed for local testing |

**Optional form fields:**

| Field | Type | Description |
|---|---|---|
| `user_notes` | string | Free text (≤500 chars), returned unchanged in the callback |

#### Immediate Response (202 Accepted)

```json
{
  "status": "processing",
  "analysis_id": "abc123"
}
```

This response arrives within ~0.5s (just validation, no inference).

#### Synchronous Error Responses

Validation failures return `400` with a field-specific message. Missing or invalid secrets return `401 Unauthorized`. These errors are returned **immediately**, without scheduling any background work.

#### Callback POST (Background)

When inference completes, the service sends a `POST` request to `callback_url` with:

- **Header:** `X-Internal-Secret` (same value as `ML_SERVICE_SECRET`, so the receiver can verify authenticity)
- **Header:** `Content-Type: application/json`
- **Body:** JSON with this shape:

```json
{
  "analysis_id": "abc123",
  "skin_type": "combination",
  "sensitive": false,
  "confidence": 0.9,
  "disagreement": false,
  "final_scores": {
    "sebum_level": 61.2,
    "hydration_level": 50,
    "acne_frequency": 47.5,
    "pore_size": 55,
    "sensitivity_score": 30,
    "roughness_score": 40,
    "tightness_score": 30
  },
  "raw_debug": {
    "quiz_oiliness": 65,
    "image_oiliness": 55.5,
    "quiz_acne": 45,
    "image_acne": 50,
    "skin_type_probabilities": {"oily": 0.5, "normal": 0.3, "dry": 0.2},
    "acne_probabilities": {"mild": 0.7, "severe": 0.3}
  },
  "user_notes": null,
  "timestamp": "2026-08-01T00:00:00+00:00"
}
```

**Retry logic:** If the callback POST fails (network error or non-2xx response), it retries up to 3 times with 2-second delays between attempts. All failures are logged with the `analysis_id` for traceability. If all retries fail, a clear `ERROR` log is emitted.

**Timeout observability:** If inference takes longer than 90 seconds, a `WARNING` log is emitted (observability only, not a hard kill).

## Render Deployment

1. Sign in to Render and choose **New Web Service**.
2. Connect your GitHub repository and set **Root Directory** to `ML-Service`.
3. Add `ML_SERVICE_SECRET` as an environment variable (use a strong random value).
4. Deploy. Render builds the Docker image, downloads both models during the build, and starts Uvicorn.
5. Set the live URL as `ML_SERVICE_URL` in your Next.js environment variables.
6. Set `ML_SERVICE_SECRET` to the same value in Vercel. Do not expose it as a `NEXT_PUBLIC_` variable.

The free tier has 512MB RAM. The service is optimized (sequential model loading + INT8 quantization) to stay well under this limit (~242MB peak).
